## 0. 물어보신 것 — PLCD

> **PLCD = 선봉 설계자**
> **"판 짜고 바로 말하는 사람"**
> 순서를 먼저 그리고, 자기가 끌고 가고, 문제는 그 자리에서 짚고, 결론부터 말한다.

| | |
|---|---|
| **강점** | 시작이 빠르고 문제가 오래 묵지 않는다 |
| **보완할 점** | 속도에 못 따라오는 사람이 말할 틈을 잃는다 |
| **팀에서 좋은 자리** | 전체 일정과 결정을 주도하는 자리 |

---

## 1. 이름을 2단으로 만든 이유

4축을 한 단어에 우겨넣으면 반드시 두 축이 죽습니다. **앞 두 축은 "일하는 방식", 뒤 두 축은 "말하는 방식"**이라 성격이 다르므로 나눕니다.

```
[계획성 × 주도성] = 일하는 방식 4가지
[갈등대응 × 소통] = 말하는 방식 4가지
                    → 4 × 4 = 16유형
```

이러면 **16개를 외울 필요가 없습니다.** 4 + 4만 알면 조합으로 읽힙니다. 그리고 새 축을 추가해도 체계가 안 무너집니다.

### 일하는 방식 4

| 코드 | 이름 | 뜻 |
|---|---|---|
| **PL** | 판 짜는 형 | 순서를 먼저 그리고 자기가 끌고 간다 |
| **PS** | 길 닦는 형 | 순서를 그려서 남이 쓰게 한다 |
| **AL** | 먼저 뛰는 형 | 일단 시작하고 남들을 끌어당긴다 |
| **AS** | 바로 붙는 형 | 일단 붙어서 필요한 걸 채운다 |

### 말하는 방식 4

| 코드 | 이름 | 뜻 |
|---|---|---|
| **CD** | 바로 말하는 형 | 그 자리에서 짚고 결론부터 |
| **CI** | 돌려 짚는 형 | 반드시 짚되 말투는 부드럽게 |
| **HD** | 짧게 고르는 형 | 각을 안 세우되 말은 간결하게 |
| **HI** | 감싸는 형 | 부드럽게, 배경부터 |

## 3. 유형 페이지에 반드시 들어갈 4번째 칸

강점·보완만 쓰면 **MBTI 설명문과 구별이 안 됩니다.** 우리 출력물은 유형 설명이 아니라 **팀 배치**입니다.

**"팀에서 좋은 자리" 칸이 우리와 MBTI를 가르는 유일한 칸입니다.** 절대 빼지 마세요.

| 이렇게만 쓰면 MBTI | 우리가 추가하는 칸 |
|---|---|
| 강점 · 보완할 점 | **팀에서 좋은 자리** |
| "당신은 이런 사람입니다" | **"이 팀에서 당신은 여기 서면 좋습니다"** |

그리고 **같은 유형이라도 팀 구성이 다르면 배치 제안이 달라져야 합니다.** PLCD가 혼자면 리드를 맡지만, PLCD가 셋이면 그중 하나는 검토 자리로 갑니다. `suggest_roles` 도구가 이걸 처리합니다 — **유형 페이지는 고정, 배치 제안은 동적**입니다.

## 4. 한 줄만 지키면 방어선이 삽니다

유형을 출력하기로 했으니, 심사위원의 *"MBTI랑 뭐가 다르냐"*에 답할 준비만 해두면 됩니다. 화면 상단 한 줄로 끝납니다.

> **"협업 스타일 8문항 결과입니다. 성격 유형 검사가 아니며, 이 팀에서의 자리를 제안하기 위한 것입니다."**

**"성격 유형"이라는 말만 안 쓰면 됩니다.** 그리고 답변 문장:

> *"MBTI는 성격 전반을 봅니다. 저희는 협업 행동 4개만 보고, 출력이 유형 설명이 아니라 **이 팀에서의 배치**입니다. 같은 유형이라도 팀이 다르면 다른 자리를 제안합니다."*

## 5. 이 표가 벡터 DB `cases` 인덱스의 절반입니다

16유형 × (한 줄 + 강점 + 보완 + 자리)를 그대로 임베딩하면 **개인 단위 검색**이 되고, `faultline.py` 진단 5종 + 주도성 3종을 문단으로 쓰면 **팀 단위 검색**이 됩니다.

| 인덱스 항목 | 개수 | 출처 |
|---|---|---|
| 개인 유형 케이스 | **16** | 이 문서 §2 — **오늘 밤 바로 넣을 수 있습니다** |
| 팀 패턴 케이스 | 10 | `FAULTLINE_SPEC.md` 진단 5종 + 주도성 3종 + 소통 갈림 + 계획 한쪽 |
| 논문 근거 | 10 | 오픈액세스 초록 |

> **§2 표가 이미 16개 케이스입니다.** B는 논문부터 찾지 말고 이걸 먼저 인덱싱하세요 — 오늘 밤 관문 8(검색 1회 성공)이 이걸로 통과됩니다.

## 6. 코드에 넣을 형태

```python
WORK_STYLE = {
    ("P", "L"): ("판 짜는 형", "순서를 먼저 그리고 자기가 끌고 간다"),
    ("P", "S"): ("길 닦는 형", "순서를 그려서 남이 쓰게 한다"),
    ("A", "L"): ("먼저 뛰는 형", "일단 시작하고 남들을 끌어당긴다"),
    ("A", "S"): ("바로 붙는 형", "일단 붙어서 필요한 걸 채운다"),
}
TALK_STYLE = {
    ("C", "D"): ("바로 말하는 형", "그 자리에서 짚고 결론부터"),
    ("C", "I"): ("돌려 짚는 형", "반드시 짚되 말투는 부드럽게"),
    ("H", "D"): ("짧게 고르는 형", "각을 안 세우되 말은 간결하게"),
    ("H", "I"): ("감싸는 형", "부드럽게, 배경부터"),
}

def type_code(m):
    return ("P" if m["plan"] else "A") + ("L" if m["drive"] else "S") \
         + ("C" if m["conflict"] else "H") + ("D" if m["comms"] else "I")

def type_name(code):
    w = WORK_STYLE[(code[0], code[1])][0]
    t = TALK_STYLE[(code[2], code[3])][0]
    return f"{w} · {t}"        # 예: "판 짜는 형 · 바로 말하는 형"
```

**별칭(선봉 설계자 등)은 딕셔너리 16개로 따로 둡니다.** 조합 이름은 자동 생성되고, 별칭은 사람이 쓴 것이라 둘 다 있으면 화면이 풍부해집니다.

## 7. 축이 갈린 사람 처리

설문 2문항이 갈리면(Q1=P, Q2=A) 그 축은 **중립**입니다. 유형 코드에는 다수 쪽으로 배정하되, 화면에 표시하세요.

> **"PLCD** — 단, 계획성 축은 뚜렷하지 않습니다(2문항이 갈렸습니다)."

**뚜렷하지 않은 축은 마찰 규칙 트리거에서 제외합니다.** 억지로 판정하지 않는 게 신뢰를 만듭니다.
