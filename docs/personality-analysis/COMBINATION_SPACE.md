# 경우의 수는 530만인데 왜 케이스가 11개인가


> 📍 **진입점은 `README.md` 입니다.** 이 문서는 근거 문서입니다 — 결정 현황·오늘 할 일·심사위원 Q&A는 README 에 있습니다.

> 2026-08-27 · 팀 질문에 대한 실측 답변 · 스크립트 `space_test.py` · `space_test2.py` · `make_pair_matrix.py`
> **결론부터: 11개는 "팀 유형 11가지"가 아니라 "출력 규칙 11개"입니다. 그런데 실측해보니 늘려야 할 곳이 따로 나왔습니다.**

---

## 0. 먼저 정정 — 유형 판정은 틀리지 않았습니다

앞선 문서에서 제가 팀 의견을 잘못 읽었습니다. 바로잡습니다.

| | |
|---|---|
| 팀이 말한 "유사도" | **개인 조합 점수 + 팀 전체 조합 점수** — 축별 방향을 적용한 가중 합 |
| 제가 읽은 "유사도" | 코사인 벡터 유사도 |

**팀 안이 맞습니다.** 그건 `chemistry_v2.pair_fit()`(개인 조합)과 `compute_chemistry()`(팀 전체)로 이미 구현돼 있습니다. 제가 기각한 건 코사인이지 조합 점수가 아닙니다.

그리고 **"6문항 다수결로 유형을 정한다"도 맞습니다.** 유형은 결정론으로 나오고, 점수 계산은 축 값으로 따로 갑니다. 둘이 충돌하지 않습니다.

## 1. 경우의 수 — 팀 질문이 맞습니다

| 팀 인원 | 조합 수 (순서 무관·중복 허용) |
|---|---|
| 2명 | 136 |
| 5명 | 15,504 |
| 10명 | 3,268,760 |
| **2~10명 합계** | **5,311,718** |

> 중립(3:3)까지 세면 개인 프로필이 `3^4 = 81`가지가 되어 더 커집니다.

**530만 대 11.** 질문이 나올 수밖에 없는 비율입니다.

---

## 2. 개인 조합은 유한합니다 — 136쌍, 전부 계산해 뒀습니다

무한한 건 **팀** 조합이고, **쌍** 조합은 `16C2 + 16 = 136`으로 유한합니다. 전수 계산해서 표로 냈습니다 → **`PAIR_MATRIX.md` · `pair_matrix.csv`**

```
최고 1.00  PLCD–ASCD · PLCI–ASCI · PLHD–ASHD   (일하는 방식 보완 + 말하는 방식 일치)
최저 0.00  ALCI–ALHD · ASCD–ASHI · ASCI–ASHD   (일하는 방식 동일 + 말하는 방식 어긋남)
같은 유형끼리 0.45                              (유사축은 만점, 보완축은 0점)
```

🔴 **단, 이진 입력에서는 점수 단계가 12개뿐입니다.** 136쌍이 12개 값으로 뭉칩니다. `confidence`(4:2 / 5:1 / 6:0)를 넣으면 해상도가 올라갑니다 — **`chemistry_v2.py`를 쓰는 두 번째 이유입니다.**

---

## 3. 케이스 11개는 팀 유형이 아니라 출력 규칙입니다

5명 팀 **15,504개를 전부 돌렸습니다**(81.8초).

| 무엇 | 가짓수 |
|---|---|
| 등급 | 3 |
| faultline 진단 | 5 |
| 마찰 조합 | 33 |
| **등급 + 진단 + 마찰** | **54** |
| 축 점수 벡터 | 72 |

그리고 화면에 실제로 뜨는 건 케이스 문단만이 아닙니다. 표본 3,000개로 **화면 전체**(등급 + 진단 + 마찰 + 축 점수 4개 + 쌍 순위 최고/최저)를 세면:

| 무엇 | 가짓수 | 최빈 점유율 |
|---|---|---|
| 케이스 문단만 | 46 | 14.1% |
| **+ 등급 · 축 점수 · 쌍 순위** | **2,191** | **0.4%** |

**화면 전체가 완전히 겹치는 팀은 3,000개 중 11개(0.4%)입니다.**

> 다양성은 케이스 **개수**가 아니라 **조합**에서 나옵니다. 케이스를 100개로 늘려도 화면 가짓수는 비례해서 늘지 않고, 대신 문단끼리 닮아져 구별도 테스트(`search_test.py` §3)가 깨집니다.

## 4. 🔴 그런데 실측이 진짜 문제 세 개를 잡았습니다

**케이스를 늘려야 한다는 신호는 "경우의 수가 많다"가 아니라 "한 진단에 너무 많은 팀이 몰린다"입니다.** 그 신호가 나왔습니다.

### ① faultline 진단이 한 통에 쏠립니다

| 진단 | 15,504팀 중 |
|---|---|
| **부분적으로 갈린 조합** | **59.0%** |
| 한 사람이 겉도는 조합 | 22.0% |
| 두 편으로 갈라진 조합 | 18.0% |
| 고르게 섞인 조합 | 0.6% |
| 한 가지만 다른 조합 | 0.4% |

`faultline.diagnose()`의 **`else` 분기가 59%를 먹습니다.** `RETRIEVAL.md` §3에서 우선순위를 7로 내린 게 옳았다는 게 실측으로 확인됐고, 동시에 **여기가 쪼개야 할 자리**라는 뜻입니다.

**처방** — `breadth`(갈린 축 개수)와 `balance`(하위집단 크기 비)로 3~4개로 나눕니다. 이미 계산되고 있는 값이라 케이스 문단만 쓰면 됩니다.

### ② 등급 A가 사실상 안 나옵니다

| | A | B | C |
|---|---|---|---|
| 전수 15,504팀 (게이트 적용 후) | **4.9%** | 79.4% | 15.6% |
| 표본 3,000팀 (게이트 적용 **전** 총점 기준) | 28.0% | 58.4% | 13.6% |

**게이트가 A의 약 82%를 B로 내립니다.** `axis_below_half`가 거의 항상 걸리기 때문인데, 유사 축(갈등·소통)은 무작위 조합에서 불일치가 0.5 근처라 점수가 0.5를 밑돌기 쉽습니다.

총점 분포: 최소 0.260 · 25% 0.533 · **중앙 0.588** · 75% 0.730 · 최대 1.000 (평균 0.609, 표준편차 0.136)

3등분 경계는 **0.66 / 0.54**입니다. 현행 0.70 / 0.45와 특히 하한이 크게 다릅니다.

> ⚠️ **아직 바꾸지 마세요.** 이 분포는 *무작위 조합* 기준입니다. 실제 팀은 친구·같은 학과라 더 닮았을 가능성이 큽니다 `[미확인]`. **실제 응답 20건을 받아 분포를 다시 그린 뒤 경계를 정하세요.** 다만 "A가 5%밖에 안 나온다"는 건 실제 데이터에서도 확인해야 할 위험 신호입니다.

### ③ 케이스 문단만 보면 7팀 중 1팀이 겹칩니다

최빈 조합 **14.1%**. 화면 전체로는 0.4%지만, **마찰 문단 두 개는 옆 팀과 같을 확률이 꽤 높습니다.** 현장에서 "우리 결과가 옆 팀이랑 똑같은데요"가 나오는 지점입니다.

**처방은 ①과 같습니다** — 59%짜리 통을 쪼개면 이 숫자가 같이 내려갑니다.

## 5. 그래서 오늘 밤 할 일이 바뀝니다

| 순위 | 무엇 | 왜 |
|---|---|---|
| 1 | **`부분적으로 갈린 조합`을 3~4개로 쪼갠다** (`breadth` × `balance` 기준) | 59% → 15~20%. 케이스 11 → 13~14개. 문단만 쓰면 되고 코드는 이미 값을 갖고 있다 |
| 2 | 쪼갠 뒤 `search_test.py` 재실행 | 구별도 0.75 넘는 쌍이 생기는지 확인 |
| 3 | 실제 응답 20건 수집 → 총점 분포 → **등급 경계 재보정** | A 4.9%는 등급이 일을 안 하는 상태다 |
| 4 | `confidence` 연결 (`chemistry_v2.py`) | 쌍 점수 단계가 12 → 훨씬 촘촘해진다 |

**케이스를 무작정 46개로 늘리지 마세요.** 46가지는 이미 11개 규칙의 *조합*으로 나오고 있고, 규칙마다 문단을 따로 쓰면 중복 서술이 되어 검색·구별이 나빠집니다.

## 정직한 갭

- 전수 계산은 **5명·중립 없음** 기준입니다. 중립이 섞이면 프로필이 81가지가 되어 분포가 달라집니다 `[미확인]`.
- 화면 전체 2,191가지는 **표본 3,000개** 기준 하한입니다. 전수로는 더 많습니다.
- 등급 경계 3등분 값(0.66 / 0.54)은 **무작위 조합 분포**에서 나온 것이라 그대로 쓰면 안 됩니다.
- 개인 유형 카드 16장은 이 계산에 안 넣었습니다. 넣으면 화면 가짓수가 더 늘지만, **같은 유형이면 같은 카드**라 다양성의 근거로 쓰기엔 약합니다.
